# 到点实时采集与发布修正

用户明确要求每小时3个随机发送时段，到时才采集、改写和发送。修正当前工具故障被误报为无新闻，以及提前每小时囤稿的行为。

采用现有 Python/Codex/ADB 分层；不增加外部服务。每个到期时段实时检索至多3个候选，仅核验并保存本时段选中的一条，按新 id 发布，绝不取旧队列补位。未到时段不检索。手机未知结果依旧阻断。

方案比较：继续小时批采集不符合要求；固定RSS池遗漏X/视频且需要新增源维护；保留实时搜索并验证实际工具执行最贴合现有架构。本次选择第三种。

采集保留隔离与禁用手机/本地shell工具；启用搜索所依赖的 Code Mode host，结构化记录实际搜索/打开次数与受控失败原因，零工具调用与路由故障不能记为无新闻。

每小时仍3个随机时段、实际发送间隔至少8分钟；采集必须在时段开始后进行，单次研究最多360秒，提交窗口最多10分钟且不跨小时，末个计划最迟第50分钟。窗口耗尽不补发，无法确认来源不编造。网络/设备故障时不能承诺必达，结果明确可观察。
